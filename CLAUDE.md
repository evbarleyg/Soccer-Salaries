# Claude Code Setup

Treat `AGENTS.md` as shared project workflow even though it is written for Codex. Claude-specific notes below take precedence when they are more specific or when package scripts have changed.

## Project Snapshot

- Static site comparing soccer team salaries: vanilla JS + a Python data updater.
- Entry: `index.html` + `app.js`; shared helpers in `spend-utils.js`.
- Data pipeline: `scripts/update_pl_data.py` populates `data/teams.json`.
- Build/deploy: GitHub Pages via `.github/workflows/deploy-pages.yml`; data refresh via `.github/workflows/update-data.yml`.

## Claude Workflow

- Start non-trivial work by naming assumptions and a short plan.
- Make changes without asking first. The owner has given standing approval for feature work in this repo, including large or architectural changes, new files/folders, commits and pushes to the working feature branch, and opening/updating its PR — proceed and report outcomes rather than pausing for confirmation. Still ask before destructive operations (history rewrites, force-pushes, deleting others' work) or anything security-sensitive.
- Do not overwrite user or Codex changes in the worktree. Read dirty files before touching them and preserve unrelated edits.
- Prefer `rg` / `rg --files` for search.
- Use existing project patterns before adding abstractions or dependencies.

## Commands

- Lint: `npm run lint`
- Typecheck: `npm run typecheck`
- Test: `npm run test`
- Build: `npm run build`
- Full check: `npm run ci`

## Data And Safety

- `data/teams.json` is generated by `scripts/update_pl_data.py` (curls third-party sites). Treat `/tmp/*.html` caches as inputs only.
- Anything in `.github/workflows/` publishes externally on push/merge; treat changes as deploy-affecting.
- Pushing to the working feature branch and opening/updating its PR is pre-approved. Do not deploy manually or rewrite history (force-push, reset) without explicit user approval.

## Final Response Shape

After code changes, include a short changelog, validation commands run (or clearly state what was not run), risks/edge cases, suggested hardening follow-ups, and a clickable preview/live URL when applicable.
